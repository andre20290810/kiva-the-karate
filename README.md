# KIVA THE KARATE — セーパイ（2D・実写連続画像）

中央の人物（背景透過の実写連続画像 412 枚、0.2 秒間隔）の型を見ながら、動きに合うコマンド（Y 呼吸／X 構え／A 打撃／B 旋回）を
入力するリズムゲームです。成功すると人物に重なるエフェクトが出ます。譜面は編集モードで何度でも調整でき、JSON で保存できます。

旧版の 3D 表示（人体モデル・3D シーン・表示切替）は廃止しました。ページは `app/` だけを読み込み、公開用の `dist/` にも 3D の
コード・素材は入りません（`tools/build-dist.mjs` が検査）。

## 起動

```bat
npm install            :: playwright-core（ブラウザ確認用）だけ
npm start              :: http://localhost:8177/
npm test               :: 判定・長押し・AUTO・JSON 検証・配置の単体テスト
npm run test:browser   :: 実素材でのブラウザ確認（npm start を別に起動しておく）。ほかに test:audio・test:bgm・test:editor・test:chart・test:scores・test:lanes・test:widths・test:compare・test:official
```
`?fresh=1` を付けると、自動保存した編集内容を使わずに初期譜面で起動します。

## 画面

上から「背景付きのステージ」「操作パネル」。向きは表示領域の縦横比で決め（横長 = 横向きの背景、縦長 = 縦向きの背景）、
回転・リサイズしても再生位置・譜面の編集内容・AUTO は保たれます。

- **縦向き**: 背景は縦横比を保って全体を収め（余白は道場の色）、その矩形の中央に胴体の中心（両肩と両腰の中点）を置きます。
  直立時の全高は背景の高さの約 55%（`display.referenceHeightRatio`）。全コマがレーンの下〜背景内に収まらない画面では小さくします。
- **横向き**: 背景は表示領域を余白なく埋めます（cover。上下左右は切れてよい）。人物は背景とは別の前景で、左右の中央に置き、
  直立時の全高が表示領域の高さの 87%（`display.landscapeHeightRatio`）。実際に見える人物の高さは 412 コマで表示領域の 65〜97%
  （中央値 75%）。足元は全コマの下方向の広がり（99.5 パーセンタイル）が下端に収まる高さに固定し、頭や腕を上げたコマはレーンと重なります。
  表示順は奥から「背景 → レーンの背景・枠 → 背面のエフェクト → 流れるノーツ（文字・長押しの線・終端・光） → 人物 → 見出し・ボタン配置の案内・判定線・判定位置の火」。
  流れるノーツは人物の後ろを通り、人物と重なる所では人物が手前（透過 PNG の透明な部分からはノーツが見え、四角く隠しません）。レーンの位置は変えていません。
  レーンと HUD はノッチの安全域の内側に置きます。
- **大きさの基準**: 倍率はコマ共通で、撮影距離による体格の変化だけを胴の長さ（前後のコマで強く平滑化）で補正します。
  しゃがみ・蹴りで外接矩形が変わっても拡縮せず、位置も跳ねません。離れた小さな塊（ゴミ・床の反射）は基準にしません。
- **4 レーン**: 背景の上部に上から Y・X・A・B。右から左へ流れ、左の判定線で押します。ノーツの位置は「判定時刻までの残り時間 ÷
  先読み時間（`settings.laneLeadSeconds`）」で決めるので、縦横でレーンの長さが違ってもタイミングは同じです。
- **漢字のノーツ**: ノーツは四角い枠ではなく文字そのもの（息＝Y、構＝X、撃＝A、旋＝B。`app/config.js` の `glyphs`）。
  字体は太字の行書体（Yuji Mai、SIL Open Font License。`app/fonts/` に「息構撃旋」の 4 文字だけを切り出した Web フォントを同梱し、
  iPhone・PC で同じ字形）。読み込み後に 4 文字の外形を実測して大きさと中心をそろえ、筆のはみ出し・縁取り・影・光が切れない余白を取ります。
  読み込めないときは端末の字体で表示します。時刻・成績などの説明文は読みやすい字体のままです。
  黒い縁取りと影で背景から浮かせます。レーン見出しは「息／Y」など、画面のボタンも漢字を大きく、Y・X・A・B を小さく併記。
  見出しの右に**ボタン配置の案内**（4 つのボタンを菱形に配置。上 Y・右 B・下 A・左 X で固定）。その行のボタン（息は上の Y、構は左の X、
  撃は下の A、旋は右の B）だけを色と明るさで強調し、他の 3 つは控えめに表示。見出し・案内・判定線の間は余白を空けます（幅は実測）。
  判定位置は案内の右に移りますが、ノーツの位置は判定位置からの残り時間で決めるので、判定位置に着く時刻 = 正解の時刻のままです。
  流れる文字・長押しの終端・判定位置の火は、左端の判定の文字（見出し）と同じ大きさ・太さです（縦横とも同じ基準）。
  呼吸の長押しは始端と終端の両方が「息」で、間をレーンに平行な直線で結びます（線の長さ = 長押し時間）。
- **成功の火**（`app/glyphfire.js`）: 成功すると判定位置の文字そのものに赤い火が灯ります（文字の形から立ち上がる炎・赤熱・火の粉と余韻。
  文字は読めるまま）。呼吸は正しく保持している間に火が育ち、完了で強く灯ります。MISS・早すぎる解除では灯りません。
  火はノーツより先に描くので、次に流れてくるノーツを覆いません。AUTO も同じ演出です。
- **人物のエフェクト**（`app/fx.js`。番号は `app/effects-catalog.js` で固定）: ノーツごとに番号で選びます。

  | 番号 | 名称 | 内容 | 向き | 既定のコマンド |
  |---|---|---|---|---|
  | 0 | エフェクトなし | 人物には何も出さない（判定位置の文字の火は出る） | — | — |
  | 1 | 呼吸の気 | 人物の内側だけを巡る気の流れ・光の帯・粒子 | なし | 息（Y） |
  | 2 | 構えの発光 | 輪郭の光・体の上を走る光・胸元の閃光 | なし | 構（X） |
  | 3 | 打撃のエネルギー | 拳・足から攻撃方向へ伸びる光と火花・残像 | あり | 撃（A） |
  | 4 | 旋回の残像と風 | 直前のコマの残像・体を巻く空気 | あり（左右） | 旋（B） |

  番号 5（背後にまとう炎）は 2026-10-21 に廃止し、欠番です（再利用しない）。保存済みの設定や読み込んだ JSON に 5 があれば、
  息のノーツは 1、それ以外は 0 に置き換えます（時刻・コマンド・位置・強さなどほかの編集内容はそのまま。炎だけの高さ・幅は外す）。

  **呼吸の気（No.1）**: 人物の透過画像のアルファで切り抜き、人物が写っている所（頭・胴体・腕・脚）の内側だけで動かします。
  腕と胴体・脚の間などの透明な所や輪郭の外には、光・粒子・ぼかしも出しません（作業用画像に描いてから、画面と同じ画素の格子で
  人物のアルファを最後に掛ける）。気の流れが下から上へ巡り、光の帯が足元から頭へ上り、小さな光が体の中を上ります。
  色を重ねるだけで加算しないので、顔や道着の質感は白く潰れません。長押し中は進み具合で強まり、成功で体の中心から全身へ光が広がって収まります。
  人物の画像の切り替え・位置と倍率の補正・画面の回転には、表示している人物と同じ変換で追従します。一覧のプレビューも同じ描画です。
- **メモリ**: 切り出し済み WebP（合計 約 7 MB）を最初に全部取得し、デコード済み画像は再生位置の前後だけ（最大 48 枚）保持します。

## 操作

| 入力 | 意味 | 方式 |
|---|---|---|
| Y | 呼吸を整える | 長押し（開始の時刻・必要な時間の保持・早すぎる離しを判定） |
| X | 構える・構え直す | 単押し |
| A | 突き・蹴りなどの打撃（譜面の `action` で突き／蹴り／打ちを区別） | 単押し |
| B | 大きな向きの変更・旋回 | 単押し |

キーボード: Y X A B（押しっぱなしの自動リピートは無視）／ Space 開始・一時停止 ／ R リトライ。
画面のボタンはタッチとマウスの両方で使え、二重には数えません。ゲームパッド（標準配置）は **位置** で対応します:
上 = Y、左 = X、下 = A、右 = B（Nintendo 配置のコントローラーは印字と位置が違うので、画面のボタン名で確認してください）。
入力欄にフォーカスがある間、Y X A B はゲーム操作になりません。

### タイミング判定（⚙設定 →「タイミング判定」）

ずれ = 入力した時刻 − 正解の時刻（マイナス = 早い、プラス = 遅い）。境界ちょうどは内側（|ずれ| ≤ 幅）。値は譜面の `settings` に入り、
編集モード・譜面 JSON の入出力と同じ値です（別の設定は作りません）。

| 項目（`settings`） | 初期値 | 範囲 | 意味 |
|---|---|---|---|
| PERFECT（`perfectWindowMs`） | 60 | 10〜200 | ±60ms＝正解時刻の 0.06 秒前〜0.06 秒後で PERFECT |
| GOOD（`goodWindowMs`） | 120 | 20〜300 | PERFECT の外側から ±0.12 秒まで GOOD |
| 許容限界（`missWindowMs`） | 180 | 30〜400 | GOOD の外側〜±0.18 秒は MISS（そのノーツを使う）。外側の入力は「余分な入力」 |
| 息の押し始め（`holdStartWindowMs`） | 120 | 10〜400 | 長押しの押し始めの GOOD の幅（PERFECT は PERFECT の幅）。この項目の無い譜面は GOOD と同じ |
| 息の早離しの許容（`holdReleaseWindowMs`） | 150 | 0〜1000 | 終わりの 0.15 秒前より後に離せば成功。それより前は早離し（MISS） |
| 入力補正（`inputOffsetMs`） | 0 | −300〜300 | ＋で押した時刻をその分早い時刻として判定（入力が遅れて届く場合に＋） |

大小関係（PERFECT ≤ GOOD ≤ 許容限界、PERFECT ≤ 息の押し始め ≤ 許容限界）・範囲・1ms 単位の整数を検証し、正しくない値は保存できません。
「初期設定に戻す」で上の初期値に戻して保存します。判定の条件はプレイの開始時（▶ 開始・リトライ）に確定し、プレイ中に保存した変更は次のプレイから使います。

### 成績（終了後に自動で表示。いつでも「成績」ボタンで開く）

**横幅**: 成績（全画面）と設定（⚙）は編集画面と同じ横幅です（画面の左右から 10px ＋ セーフエリア。最大幅の制限なし）。
3 画面の左右の端がそろい、中身（グラフ・照合タイムライン・カード・設定の項目）は広がった幅を使います。文字・ボタンの大きさは変えず、
グラフは等倍で描いて目盛りの間隔を広げ、カードは 1〜5 枚（画面幅による）を並べ、設定は広い画面で 2 列にします。
ページ全体は横にスクロールしません（照合タイムラインとカードの列だけが横スクロール）。

- **記録**（ノーツごと）: ID・技・正解時刻・入力時刻・入力ボタン・ずれ（ms）・判定・入力方法（キーボード・タッチ・マウス・ゲームパッド・AUTO）。
  入力補正があるときは補正前の時刻・ずれも残し、成績は判定に使った補正後のずれで表示します。判定と記録は同じゲームの時間軸です。
  キーの自動リピート・タッチの重複は記録しません。判定範囲外・間違ったボタンは「余分な入力」として別に記録し、後から成功ノーツへ付け替えません。
  入力のない MISS には入力時刻・ずれを入れません。息は押し始め・離した時刻・必要な保持時間（長押し − 早離しの許容）・実際の保持時間・
  早離し／途中解除を記録します（必要な時間を保持して成功が確定した時刻は、離した時刻とは別に記録）。
- **概要**: スコア・最大コンボ・成功率・PERFECT／GOOD／MISS（入力なし・範囲外の入力の内訳）・平均絶対誤差（早い・遅いを相殺しない）・
  平均符号付き誤差（早押し／遅押しの傾向）・誤差の標準偏差・息／構／撃／旋ごとの成績。誤差は入力のあったノーツだけで計算し、対象件数を併記。記録が無いときは「—」
- **タイミング**: 中央が正解（0ms）、左が早い・右が遅い。PERFECT・GOOD の範囲を帯で示し、各入力を点で描く（●PERFECT ▲GOOD ✕MISS。色だけに頼らない）。
  グラフのすぐ上に凡例（点の形・色、PERFECT／GOOD の範囲（その記録の判定幅）、中央線 = 正解、左 = 早押し・右 = 遅押し）。
  比較では今回（塗りつぶし）と比較する記録（白抜き）も凡例に出します。凡例とグラフは同じ表示設定（`VIS`）から作ります。
  技で絞り込み。入力のない MISS は 0ms に描かず一覧で別に表示
- **照合タイムライン**（「照合・ノーツ詳細」の主表示）: 編集画面のタイムラインと同じ時間軸（0 秒〜演武の終わり約 82 秒、左から右へ。
  目盛りは 1 秒と 0.2 秒で、編集画面と同じ `app/timeline.js`）。技ごとに「正解」の段と「入力」の段（上から Y・X・A・B、編集画面と同じ順）、
  最後に「不採用・余分な入力」の段。同じ時刻は同じ横位置です。正解の段に技の字と色、息は正解の保持区間。入力の段に採用した入力
  （押したボタン・ずれ・● PERFECT ▲ GOOD ✕ MISS）と、正解から採用した入力への線（横の距離 = 早い／遅い）、息は実際に押していた区間と離した位置。
  入力なしの MISS は正解の段に ✕ を付け、入力の段には何も描きません。不採用・余分な入力は専用の段だけに描きます。
  ＋／－／全体で拡大・縮小（1 秒 = 4〜1000px。最大で 10ms = 10px。中央の時刻を保つ）、Ctrl＋ホイールでも可。1 秒 = 100px 以上では判定の範囲も描きます。
  文字は実測した幅で重ならない位置に置き、入らないときは短くするか省きます（印は必ず描く）。凡例つき。
  ノーツや入力を押すと、その時刻の主人公の画像（正解時・入力時）と詳細カードに移り、カードを押すとタイムラインのその位置を選びます。
  表示はそのプレイの記録（記録した譜面のノーツ・入力・判定条件・時間軸の長さ）だけから作ります。
- **ノーツ詳細**: 選んだ箇所の詳細表示。時刻順の横スクロールのカード（スマホ縦は 1 枚、横向き・タブレットは 2 枚、PC は 3 枚ずつ。
  スマホはスワイプ、PC はスクロールバーか ◀ ▶）。並んだカードは高さと項目（見出し・画像・正解・入力・判定・小さな時間軸・息・関係する入力）の位置が
  そろいます（CSS の subgrid。長い内容は折り返し、行の高さを広げます）。小さな時間軸の印の文字は番号つきで 2 段に置き、「正解 0」は別の段です。「12／59件」で位置を表示し、
  すべて／PERFECT／GOOD／MISS と 息／構／撃／旋 で絞り込み。各カードに番号・ID・正解の技とボタン・正解時刻・押したボタンと入力時刻・
  「110.0ms 遅い → ▲ GOOD」のような文章のずれと判定、正解時と入力時の主人公の画像（コマの時刻表から選ぶ。コマは 0.2 秒間隔なので同じ画像になることがあり、
  正確なずれは数値で表示）、補正後の時間軸のミニタイムライン（正解・判定範囲・実際の入力）。入力のない MISS は「入力なし」で入力時の画像を出さず、
  ボタン違いは要求と押したボタンを分けて表示。近くの余分な入力は「判定に使っていない」として時刻順に並べ、採用した入力に印を付けます（付け替えはしません）。
  息は正解の開始・終了、押下・解除、必要／実際の保持時間、早離しの有無。古い記録で欠けている項目は推測せず「記録なし」。
  過去の記録はその記録の譜面・判定幅で表示し、今の譜面から計算し直しません。カードの下に余分な入力の表
- **比較**（`app/compare.js` が計算、`app/compare-view.js` が画面）: 2 つの方式。どちらも保存済みの記録（プレイ当時の譜面・入力・判定条件）だけを使います。
  - **記録の比較**: 履歴で 2 件以上をチェックして「選択した○件を比較」（直近のプレイを含めなくてよい。比較画面からも追加・解除）。
    各記録に日時順で色と記号（A・B・C…）を割り当て、画面全体で共通。改善量の基準は選べます（初期は最も古い記録）。
    全体・技ごとの成功率・PERFECT／MISS 率・平均絶対誤差・符号付き誤差・ばらつき・改善／悪化したノーツ数、3 件以上なら日時順の推移。
    **全編の照合**: 編集画面と同じ時間軸（0 秒〜演武の終わり。終わりは記録の譜面の長さ）で、上段に正解（息・構・撃・旋と保持区間）、
    その下に記録ごとの行（入力の位置と判定、入力なし、余分な入力、息の押していた区間と離した位置）。全行が 1 つの図なので横スクロール・拡大は連動し、
    左の記録名は固定。拡大すると ms の文字（重ならない位置）。ノーツを選ぶと全記録の入力・符号付き／絶対誤差・判定・基準からの改善量と、
    正解時・入力時の主人公の画像。**ノーツ別の比較表**（行 = ノーツ、列 = 記録）は改善・悪化・MISS を含む・技で絞り込み、セルから時間軸と詳細へ。
  - **期間平均の比較**: 期間 A（基準）と B の開始日・終了日、または「直近 7 日間とその前の 7 日間」「前週と今週（月曜はじまり）」「前月と今月」など。
    日付は現地時間で終了日当日を含みます。集計条件（同じ譜面・判定幅・再生速度・入力補正）を選び、手動の通しプレイだけを集計
    （AUTO・練習・途中終了は初期状態で除外、含めることも可。除いた件数と理由を表示）。期間が重なると同じ記録が両方に入ることを表示。
    全体（平均絶対誤差・符号付き誤差・ばらつき・成功率・PERFECT 率・MISS 率・息の保持の成功率・平均スコア）、技ごと、ノーツ別（共通の時間軸に
    両期間の平均誤差と改善・悪化、選ぶと画像と両期間の値）、比較表（時刻順・改善順・悪化順）、集計対象のプレイへの移動、JSON・CSV の書き出し。
  - **計算の約束**: ノーツは譜面の安定した ID で対応付け（配列の順番では結ばない）。同じ ID でも時刻・コマンド・保持時間が違えば「条件変更」、
    ない場合は「対応なし」として比較・集計に入れない。改善量 = 基準の絶対誤差 − 比較の絶対誤差（早押しと遅押しを相殺しない。プラスが改善）、
    改善率 = 改善量 ÷ 基準（基準が 0 なら「—」）、率の差は「ポイント」。入力なし・ボタン違いは誤差 0ms として扱わず MISS に数え、
    入力がない側とは ms の改善量を作らず「入力なし→GOOD」のように判定の変化で示します。息は押し始めの精度と保持・解除を分けます。
    全体の平均は対象の入力を合算（平均の平均にしない）。取り込んだ同じプレイは重複して数えません。件数は示しますが、有意性は判定しません。
    条件が違う記録も選べますが、違いを明示し（※）、同じ条件の改善とは区別します。古い記録で欠けている項目は「記録なし」。
- **区分**: 通しプレイ（最後まで）／途中終了（リトライなどで終えた）／練習（シーク・区間ループ・途中で速度変更・編集・途中から開始）。練習は通しプレイの自己ベストに入りません
- **再生速度**: ずれと判定幅は譜面の時間軸の ms（判定と同じ基準）。1× 以外ではその旨と実時間の倍率を表示します
- **履歴**: このブラウザに保存（`kiva2d.v2.history`、最大 150 件。超えたら古い練習・途中終了から消す）。各記録に日時・手動／AUTO・入力方法・
  譜面の識別（ハッシュ）・判定幅・入力補正・再生速度・BGM・概要・ノーツごとの記録・区分を入れます。履歴から開く・比較・選択して削除・
  JSON の書き出し／読み込み（成績 JSON `kiva-score-history/1`。譜面 JSON とは別の形式で、互いに読み込み・上書きしません）。
  保存できないときは画面に表示し、「成績を JSON で保存」で退避できます

**効果音はありません**（2026-10-21 に廃止）。息・構・撃・旋の音、成功・失敗の音、効果音の音量設定はなく、音を作る処理もありません。
古い保存設定に効果音の音量が残っていても読まずに消します。音は BGM（3 曲から選択）と元動画の音声だけで、それぞれ音量・ミュートを設定できます。

**AUTO**: 譜面のノーツを予定時刻ちょうどの入力として、通常プレイと同じ判定処理に渡します（Y は押して保持して離す）。
画面に「AUTO 再生中」と出て、結果は手動プレイの記録と区別されます（手動の最高記録には入りません）。
途中で切り替えても、過去のノーツをまとめて成立させたり、押したままの Y が残ったりしません。

- **公式デモ 3 件**（`charts/official-demos.json`、ID `official-demo-90`・`-70`・`-50`）: 公式に用意したシミュレーションで、実際の利用者の実績ではありません。

  **通常の判定処理に通して結果を計算**します（スコア・判定を手で書かない）。PERFECT・GOOD・早押し・遅押し・入力なし・ボタン違い・息の早離し・押し始めが遅すぎを含み、

  比較（記録の比較）で互いに、また自分の記録と比べられます（譜面・判定幅・速度・入力補正を表示、違えば明示）。自己ベスト・期間平均には入りません。
- **リプレイ**（成績の概要・履歴の「▶ このプレイを再現」）: 保存した入力ログどおりに押下・解除を実行し、早押し・遅押し・MISS・ボタン違い・早離しも
  通常の判定処理で再現します（判定・コンボ・スコア・エフェクト）。通常の AUTO（全成功）とは別の機能です。
  画面下に「公式デモ再現中」「履歴リプレイ中」と表示。記録時の譜面（ノーツの写し）・判定条件・入力補正（記録した判定時刻を使い二重に補正しない）・
  再生速度で再生し、同じ時刻の入力も記録した順に処理します。再現中の手動入力は判定に入りません。一時停止・再開・最初から・シークに対応し、
  シークではそこまでの入力から判定・スコア・長押しの状態を作り直します（二重加点なし）。終わっても成績・自己ベストには記録しません。効果音はありません（廃止のまま）。
- **入力ログ**: これからのプレイの記録には、判定への入力（押下・解除、判定に使った時刻と補正前の時刻、直前に判定を進めた時刻）・譜面のノーツの写し・
  判定ロジックの版（`JUDGE_VERSION` = 2）・開始と終了の時刻を保存します（シーク・編集で判定を作り直したプレイには残さない）。

  入力ログのない古い履歴は「この履歴はリプレイに必要な記録がありません」と表示し、結果から入力を推測しません。版が違う記録も再計算しません。

### 設定の保存とデフォルト（個人用・パスワード不要）

| 操作 | 内容 |
|---|---|
| 自動保存（下書き） | 編集のたびにこのブラウザへ自動で保存。再読み込みしても編集が消えない |
| **個人用に保存（この端末のデフォルト）** | このブラウザだけの既定にする（下書きは消える）。保存後すぐ、通常プレイと AUTO の両方で使われ、再読み込み後も維持 |
| 編集前に戻す | 最後に個人用に保存した状態（無ければ配布時の初期設定）へ戻す（元に戻すで取り消せる） |
| 配布時の初期設定に戻す | 今の公式データ（公開版の初期設定）へ戻す（この端末のデフォルトは保存し直すまで残る） |
| この端末のデフォルトを消す | 次からは（下書きが無ければ）配布時の初期設定で起動 |
| JSON を書き出す・読み込む | 譜面 JSON のファイル（パスワード不要） |

起動時は「下書き → この端末のデフォルト → 配布時の初期設定（公式データ）」の順に使います。編集欄に今どれを使っているかを表示します。
保存する内容はノーツ単位のコマンド種別・エフェクト番号・発生位置・位置の調整・向き・大きさ・強さ・持続時間で、
既存の譜面の内容と `frameOverrides` はそのまま保ちます。エフェクトの指定のない従来の JSON も読み込めます（コマンドの既定を使う）。
個人用の保存・JSON・個人の成績履歴の保存と比較は、パスワードなしで使えます。**個人用の保存では公式データ（ほかの利用者）は変わりません。**

### 公式データとして保存・公開（全利用者に配布。パスワード必須）

場所: **編集モード →「保存・読み込み」欄の下の「公式データ（全利用者に配布）」→「公式データとして保存・公開…」**。

- 対象を選んで、その部分だけを今の公式データへ重ねます（無関係な部分は上書きしない）:
  **譜面（ノーツ）**・**判定設定**・**個別エフェクト**は「いま編集中の譜面」から、**公式デモ履歴**は同梱の `charts/official-demos.json` か JSON ファイルから。
- 公開前に、対象・変更概要（例「個別エフェクト: 1 ノーツ」）・今の版・公開後の版を表示します（サーバーと同じ検証で、公開できない内容は理由を表示）。
- 「公式データとして保存・公開」を押すたびに**パスワード**を入力します（伏字。このブラウザには記憶せず、送信後すぐ消す。ログ・成績 JSON に出さない）。
  照合は**サーバー**（Cloudflare Worker `worker/official.js`）で、パスワードは secret `OFFICIAL_PASSWORD_HASH`（PBKDF2 のハッシュ）として保存しています。
  正しいときだけ保存し、違えば「パスワードが違います（保存していません）」。キャンセルは何も変えません。
  認証のない直接の API 呼び出し（401）・ほかのサイトからの送信（403）・不正な JSON（400）は拒否。失敗が 5 回続くと 15 分止め、1 分あたりの回数も制限します。
- サーバーでも JSON の形式と内容を検証し、公式デモは**入力ログから計算し直した結果と一致**するものだけを受け付けます。
- 公開すると版番号が 1 つ上がり、版と更新日時を表示します。更新前の版は保存され、同じ画面の「以前の版に戻す」で戻せます（**復元にも同じパスワード**）。
- **版の競合**: 画面を開いた後にほかの人が更新していたら保存せず（409）、最新を読み込んでやり直すよう表示します。
- 保存先は Cloudflare KV（binding `OFFICIAL`）で、再起動・再デプロイ後も残ります。KV が空のときは公開ビルドに同梱の初期データ（版 0）を配ります。
- 反映: 新しく使い始める人と、「配布時の初期設定に戻す」「公開版の設定に切り替える」を選んだ人。**各利用者が個人用に保存した譜面・設定・成績は上書きしません**
  （起動時に「公開版の初期設定が更新されています」と案内）。

手順: ① 編集モードで変更 → ②「公式データとして保存・公開…」→ ③ 対象を選び、変更概要と版を確認 → ④ パスワードを入力して「公式データとして保存・公開」→ ⑤ 版と更新日時が出たら完了。
戻すとき: 同じ画面の「以前の版に戻す」→ パスワードを入力して「この版に戻す」（戻した内容は新しい版として公開）。

サーバーの設定（済み。作り直すとき）: `npx wrangler kv namespace create kiva-official` の id を `wrangler.jsonc` の `kv_namespaces`（binding `OFFICIAL`）へ、
`node tools/hash-password.mjs` の出力を `npx wrangler secret put OFFICIAL_PASSWORD_HASH` へ。どちらかが無いと保存は 503（サーバーの設定不足）になり、画面だけでは保存できません。
ローカルで試すときは `OFFICIAL_DEV_PASSWORD=<試験用の値> node tools/serve.mjs 8177`（メモリ上の保存先。本番のパスワードは使わない）。

シーク・ループ・リトライ・譜面の変更のたびに、その時刻以降のノーツの判定を初期化します（同じノーツを二重に加点しない、
前回の MISS が残らない）。シークより前の未判定のノーツは「対象外」として成績に数えません。

## 譜面 JSON（`charts/seipai_v2.json`、schemaVersion 1）

時間はすべて **連続画像の開始を 0 秒** とする同じ時間軸の秒数です。画像（base64 など）は含めません。

```jsonc
{
  "schemaVersion": 1,
  "gameVersion": "v2",   // 正式版（旧 ver2）。無い・"v1" の JSON は読み込まない
  "title": "セーパイ",
  "source": { "frameManifest": "assets/seipai_v2/manifest.json", "frameCount": 412, "frameIntervalSeconds": 0.2, "durationSeconds": 82.26839 },
  "audio": { "src": ["assets/seipai_v2/audio.m4a", "assets/seipai_v2/audio_opus.m4a"], "startAtTimelineSeconds": 0 },   // src は文字列か配列（先頭から順に試す）。null で音源なし
  "settings": {
    "inputOffsetMs": 0, "perfectWindowMs": 60, "goodWindowMs": 120, "missWindowMs": 180,
    "holdReleaseWindowMs": 150,   // 長押しの終了より この分 早く離しても成功
    "leadInSeconds": 2,           // 開始前の待ち時間
    "laneLeadSeconds": 2.4        // レーンの右端から判定線までの時間
  },
  "display": {
    "subjectAnchor": { "x": 0.5, "y": 0.5 },   // 胴体の中心を置く位置（背景の表示矩形内の 0〜1）
    "referenceHeightRatio": 0.55,               // 直立時の全高 ÷ 背景の高さ
    "frameOverrides": { "123": { "dx": 0.01, "dy": -0.02, "scale": 1.05 } }
  },
  "sequences": [ { "id": "opening", "label": "呼吸・構え・打撃" } ],
  "notes": [
    { "id": "n001", "time": 5.8, "button": "Y", "action": "breathe", "input": "hold", "duration": 2.6, "label": "呼吸", "sequenceId": "opening",
      "effect": { "preset": "breath", "intensity": 1 } },
    { "id": "n003", "time": 15.4, "button": "A", "action": "strike", "input": "tap", "label": "打撃", "sequenceId": "opening",
      "effect": { "preset": "strike", "anchor": { "x": 0.53, "y": 0.29 }, "direction": { "x": 0.1, "y": -1 }, "intensity": 1 } }
  ],
  "memo": [ "初期譜面の要調整箇所など" ]
}
```

| 項目 | 内容 |
|---|---|
| `button` / `action` / `input` | Y = `breathe`・`hold`（`duration` 必須）、X = `stance`・`tap`、A = `punch`／`kick`／`strike`・`tap`、B = `turn`・`tap` |
| `id` | ノーツごとに一意で変わらない ID（追加時は `n` + 連番） |
| `sequenceId` | 連続コマンドのまとまり（`sequences` の id）。各ノーツは個別に判定 |
| `effect.anchor` | 元の 720×1280 画像内を 0〜1 にした打撃点。中央配置・拡大縮小と同じ変換で画面に置く |
| `effect.direction` | 攻撃の向き（画面の右 = +x、下 = +y） |
| `effect.intensity` | 0〜2（PERFECT は 1 倍、GOOD は約 0.6 倍で表示） |
| `display.frameOverrides` | キー = コマ番号（0〜411）。`dx`・`dy` は背景の表示矩形の **高さ** に対する割合のずらし量、`scale` は自動倍率に掛ける倍率（0.2〜5） |

読み込み時は、形式・版・時刻の範囲・長押し時間・ID の重複・ボタンと action の対応・同じボタンの長押しとの重なり・
連続コマンドの参照・補正値を検証します。不正な JSON はメッセージを出して拒否し、今の編集内容は変わりません。
判定済みフラグやコンボなど、プレイ中だけの状態は保存しません。

## POV AR / 正解動作ガイド（`pov.html`。ゲームの ⚙ 設定の「POV AR / 正解動作ガイドを開く」から）

ゲーム本体とは**別のページ**です。ゲームのロジック・譜面・タイミング・成績・保存データには触れません（ゲームは POV のコードも Three.js も読み込みません）。
表示は **2D 背景を用いた主観視点シミュレーション**で、実空間に固定する AR ではありません（背景は固定の 2D 画像。頭の動きに合わせた視差・頭部位置の追跡・IMU 連動はありません）。

- **背景**: `DOJO`（既定。`assets/dojo_pov.jpg` を縦横比を保って中央クロップ）／ `LIVE CAMERA`（選んだときだけ getUserMedia。HTTPS のページのみ。拒否・非対応・使用中は理由を出して道場の画像で続ける）／ `VIDEO FILE`（端末の動画を背景に。選ぶまで道場の画像は消えない。再生・シークに時刻を合わせる。時刻のずれを指定可）。「比較画像」で背景のみと重ねた結果を並べて保存できます。
- **視点**: `EYE / 一人称`（既定。演者自身の目の位置に置き、演者の頭の向きで前方を決める。頭は描かない。足は視野に入ったときだけ描く。near 0.03 m）／ `OVER SHOULDER / 背面確認`（頭の後ろ 0.4〜0.8 m・少し上から肩越しに見る**確認用の第三者視点**）／ `THIRD PERSON / 全身検証`（固定位置から全身を見るデバッグ用）。
- **表示**: `SOLID`（既定。人体モデル）／ `SKELETON`（33 点と骨の線。補間・低信頼度は橙、範囲外は赤。体に隠れても見える）／ `BOTH` ／ `OFF`。
- **操作**: 再生／停止・コマ送り（0.2 秒）・シーク・速度 0.5／1／1.5×・「0.2 秒のコマのまま（補間しない）」、調整（透明度・スケール（目を中心に拡大縮小）・FOV（縦）・視線の上下補正・カメラの前後／左右／高さ・背面確認の距離・全身検証の方位・指の曲げ・向きの平滑化・背景の拡大／上下位置・前方の基準（頭／胴体）・左右反転（既定 OFF）・視線の水平線・元映像のコマ）、リセット。操作パネルはたためます（スマホ縦でボタン 44px 以上）。調整の値だけ端末に保存し、背景・視点・表示は毎回 DOJO / EYE / SOLID から始めます。
- **時間グラフ**: 頭（水色）と胴体（橙）のヨー、見失い（赤）・警告（橙）のコマ。タップでシーク。「診断」に各コマの頭のヨー／ピッチ・頭と胴体の差・前コマからの変化・頭の点の信頼度・反転の疑い・カメラ位置・骨の当てはめのずれを表示します。

### 正解動作データ（重要）

- セーパイの連番画像は 720×1280・`frame_0000`〜`0411`・0.2 秒間隔（412 コマ、0〜82.2 秒）。**412 コマの人体 3D 関節座標はまだ推定していません**。`assets/seipai_v2/manifest.json` の `joints` は 2D の画像座標で、3D の正解とはみなしません（POV では使わず、右下の「元映像のコマ（2D）」で時刻の対応を確認するだけ）。
- 3D データを読み込むまでは **`DEMO / 人工的な動作、空手の正解ではありません`** と表示し、運動学で作った人工的な動き（突き・受け・蹴り・90° ずつの旋回）を見せます。関節とメッシュ・視点の確認用で、空手の型の正解ではありません。
- 読み込んだデータも「推定値。正解の型との一致は未検証」と表示します。ファイルは端末の中だけで使い、送信・保存・書き換えはしません（原データの文字列と解析結果は凍結し、表示用は別に作る）。

**入力形式**（MediaPipe Pose Landmarker の `worldLandmarks`。33 点・メートル・腰の中点が原点・y が下・z は奥。関節の番号と名前は MediaPipe と同じ `0 nose` 〜 `32 right_foot_index`）

1. CSV（縦長。1 行 = 1 関節）: 見出し `time,joint,x,y,z,visibility`（`time` の代わりに `timestamp_ms` か `frame`（× 0.2 秒）でも可。`joint` は番号か名前。信頼度は `visibility`／`confidence`／`presence` のどれか。無ければ 1）。`# coordinateSystem=y-up` `# interval=0.2` の注記行を書けます。画面の「入力形式の見本 CSV（DEMO の値）」で見本を保存できます。
2. CSV（横長。1 行 = 1 コマ）: `time,x0,y0,z0,v0,…,x32,y32,z32,v32` または `time,nose_x,nose_y,nose_z,nose_visibility,…`。
3. JSON: `{"format":"kiva-pose3d/1","interval":0.2,"coordinateSystem":"mediapipe-world","frames":[{"t":0,"landmarks":[[x,y,z,v],…33]}]}`、または MediaPipe の結果の形 `{"frames":[{"timestamp_ms":0,"worldLandmarks":[[{"x":…,"y":…,"z":…,"visibility":…},…33]]}]}`（複数人なら 1 人目）。画像座標の `landmarks` しか無いものは拒否します。

**検証と処理**（`app/pov/pose.js`）: 読めない行・重複・時刻の並び（並べ替えて警告）・同じ時刻の重複（エラー）・画像の正規化座標（エラー）・単位（肩幅から mm／cm を検出してエラー）・腰から 3 m を超える値（欠損扱い）・33 点に足りないコマ（欠損扱い）。
欠損は関節ごとに前後の有効なコマから**時間方向に線形補間**（端は近い値）。信頼度がしきい値（既定 0.5）未満の点は値を使って警告（指定すれば補間）。体の主要 12 関節のうち 4 つ以上が補間・低信頼度のコマは「見失い」。一度も値の無い顔・手・足の点は周りから推定して「実測ではありません」と表示、肩・肘・手首・腰が全く無ければ拒否。
**同期**: 0.2 秒の 412 コマの格子に合わせます（時刻が格子に乗っていればそのまま、30fps などは線形補間。データの時刻のずれを指定可。範囲外のコマは見失い）。左右反転は表示用に左右の関節を入れ替えます。床は足の点の 5 パーセンタイルを Y=0 にします（worldLandmarks は腰が原点で移動量を持たないため、演者はその場に留まります）。
「処理後のデータを JSON で保存」で、検証・補間・同期した結果（`kiva-pose3d-processed/1`、Y が上の座標）を別ファイルとして保存できます。

### 人体モデルと視点（`app/pov/rig.js`）

- 外部のモデルファイル（GLB）は使っていません（ライセンスを確認できた人体・道着のモデルが無いため）。Three.js の `SkinnedMesh` + `Skeleton` の形をコードで生成します: 連続したテーパーの上腕・前腕（肘・手首は隣の骨と重みを混ぜて連続）、手のひらと 5 本の指（各 3 節）、もも・すね・足、白い道着の上衣・袖（前腕の 6 割まで）・ズボン、黒帯、首・頭（一人称では描かない）。
- 骨の長さは読み込んだデータの全コマの中央値。各コマで関節点から骨の向きを直接決めます（肘・膝の曲がる向き、手の甲は人差し指・小指・手首の 3 点、すねは足の向きでねじれを決める）。**指の曲げは MediaPipe Pose では測れないため固定形状**（調整で変更可。実測ではありません）。
- 当てはめの品質: 各コマで「メッシュの骨の先」と「次の関節点」のずれ（骨の長さの揺れ）を mm で測り、診断に表示します（コマごと・全コマの平均と最大）。
- 視点の推定: 頭の向きは左右の耳の軸と耳の中点→鼻の向きの 2 つから求め、食い違えば「反転の疑い」として胴体（肩・腰の左右軸）の向きを使います。ピッチは耳→鼻の角度の全コマの中央値を水平とみなした差です。頭と胴体の差が 70° を超える・前のコマから 60° 以上変わる・頭の点の信頼度が低いコマは警告します。前方の基準は「頭／胴体」を切り替えられます。

**次の段階の研究課題（未実装）**: 実空間に固定する AR、頭部位置の追跡、IMU 連動、利用者の動作との自動誤差評価、412 コマの 3D 関節の推定そのもの。見た目がそれらしく見えることと、正しい 3D 位置で重ねられたことは別です。
